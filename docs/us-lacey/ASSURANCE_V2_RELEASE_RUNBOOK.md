# Assurance V2 — release and manual staging acceptance runbook

## Current release decision (2026-10-11)

**NO-GO for the production site.** The integration RC is deliberately a draft,
not yet merged into `feature/us-lacey-pilot-platform`. Source-linked candidates
and authenticated PostgreSQL end-to-end acceptance are real engineering results,
but they do not demonstrate high-quality extraction over representative
non-synthetic documents or compliance with actual broker source requirements.

Verified production Supabase `alembic_version` on 2026-10-11:
`078_us_lacey_assurance_v2_authority`. The RC includes the additive migration
`079_us_lacey_assurance_v2_claim_snapshots`. Its `us_lacey_assurance_v2_claim_snapshots`
table did not yet exist in production at the time of inspection.

Production Northflank CLI context `litoraltrace` exists on HP-JDL, but
read-only `GET /v1/projects` returned **HTTP 401** with its stored token.
Obtain/revalidate the proper scoped deployment authorization before any
Northflank changes. Do not silently deploy on Render, substitute another
provider, or print API credentials.

## Required acceptance before production rollout

1. CI, including the **mandatory** U.S. Lacey PostgreSQL Gate that runs
   `test_assurance_v2_golden_postgres.py`,
   `test_assurance_v2_filing_complete_postgres.py` and
   `test_assurance_v2_issuance_concurrent_postgres.py`, must pass, with
   zero skipped PostgreSQL acceptance.
2. A reviewed corpus of real, suitably de-identified commercial invoices,
   packing lists, bills of lading and broker entry numbers must have complete
   field-level ground truth and measurable false-support, false-association
   and missing-support outcomes. **No real documents are present in this RC.**
3. Verify tenant A/B isolation, existing audit permissions, source replacement,
   revocation, negative reuse, and atomic issue/download behavior on the
   *same* migrated PostgreSQL schema.
4. Verify the production backup/restore plan and migration 079 dry run on
   an isolated recent schema clone. Apply `alembic upgrade head` using the
   actual migrations owner, not runtime/worker credentials; validate exactly
   one Alembic head and RLS/FORCE on the candidate snapshot table.
5. Deploy **the same checked commit** to the Northflank web and worker using
   a coordinated rollback plan. Health and readiness must return 200 and
   the runtime must not contain a schema-version mismatch.
6. **Staging only:** set `US_LACEY_ASSURANCE_V2_MODE=SHADOW`,
   `US_LACEY_ASSURANCE_V2_COMMANDS=ON` and
   `US_LACEY_ASSURANCE_V2_REVIEW_JOURNAL=ON` for a private,
   isolated tenant/storage/database. Do not enable commands in production
   before regulatory and commercial approval. The literal `ENABLED` mode
   remains explicitly forbidden by code.
7. Exercise manual staging with 7 original synthetic Pack 1 PDFs under
   `tests/fixtures/assurance_v2_pdf_e2e/pack1/`, plus the separate test-only
   `SYNTHETIC_ENTRY_NUMBER_CONFIRMATION_NOT_FOR_FILING.pdf` generated by
   `tests/test_assurance_v2_filing_complete_postgres.py`. The extra document
   is **not** a customs entry and its fictional `999-9999999-9` is never
   valid evidence for real shipments.
8. Confirm current source URL/page, reviewer identity, explicit decisions for
   all required and populated optional fields, exact supplier/SKU/line, PPQ
   validity, export authorization, one immutable XML/Excel/PPQ JSON dossier,
   no duplicate event, 409 on missing or withdrawn evidence, and the
   `submitted_to_agency: false` fact in all issued preparation artifacts.
9. Validate initial release in SHADOW with commands OFF and explicitly
   verify rollback to the last known-good web/worker images while preserving
   the append-only audit trail. Never downgrade a migration that has already
   written customer audit evidence without a separately approved recovery plan.

## Exact source of authority

The PR checks are necessary but not sufficient. This product prepares
Lacey/APHIS/LAWGS data; it does not submit a filing to any agency.
Existing customer-facing production functions should continue to use the
stable legacy paths until the outstanding acceptance constraints are met.
